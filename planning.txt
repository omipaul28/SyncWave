# SyncWave – Real-Time Collaborative Music Streaming Platform

## Project Overview

**SyncWave** is a modern web-based music streaming platform inspired by Spotify, with one unique feature: **real-time collaborative listening**. Unlike Spotify Jam, where one person primarily controls playback, SyncWave allows **every member in a listening room to control the music simultaneously**. Any participant can play, pause, skip, seek, shuffle, repeat, or manage the shared queue, and all connected users stay synchronized in real time.

The application also includes playlist management, favorites, music search, synchronized lyrics, an admin panel for managing songs, and a scalable architecture using only free services.

# Main Feature

# Real-Time Collaborative Listening Room

This is the primary feature that differentiates the project.

Users can create a listening room and invite others using a Room ID or shareable link.

Unlike Spotify Jam, **every participant has equal control over playback**.

Anyone in the room can:

* Play music
* Pause music
* Resume music
* Skip songs
* Go to previous songs
* Seek to any position
* Shuffle playlist
* Change repeat mode
* Add songs
* Remove songs
* Reorder queue

There is no playback "host." The server maintains the room state and applies actions in the order they are received. A room owner exists only for room administration (for example, removing disruptive users or deleting the room).

---

# Room Synchronization

The server stores the room state:

```text
Room
 ├── Current Song
 ├── Current Time
 ├── Playing / Paused
 ├── Queue
 ├── Shuffle
 ├── Repeat
 ├── Members
 ├── Updated By
 └── Last Updated
```

Every control action follows this flow:

```text
User Action
      │
      ▼
Socket.IO Event
      │
      ▼
Express Server
      │
Update Room State
      │
      ▼
Broadcast to Everyone
      │
      ▼
All Clients Update Together
```

Example:

```text
User B presses Next

↓

Server changes current song

↓

Broadcast

↓

Every user immediately switches
```

If User C seeks to 2:10:

```text
Seek to 130 sec

↓

Server

↓

Broadcast

↓

Everyone seeks to 130 sec
```

To keep playback synchronized, clients periodically compare their playback position with the server. If the drift exceeds a small threshold (e.g., 300–500 ms), the client automatically seeks or briefly adjusts playback speed to resynchronize.

# Lyrics Feature

Each song can display lyrics.

Recommended approach:

1. When a song is played, request synchronized lyrics from a free lyrics provider (such as LRCLIB if available for that song).
2. Cache the lyrics in Firestore.
3. Future requests use the cached version.
4. If no lyrics are available, display "Lyrics unavailable."

If synchronized timestamps are available, highlight the current line as the song progresses.

# Bufferless Streaming

The system uses Cloudinary URLs for audio.

Playback flow:

```text
User clicks Play

↓

Audio URL

↓

Cloudinary CDN

↓

Browser requests small audio chunks

↓

Music starts playing immediately

↓

More chunks are loaded while playing
```

Advantages:

* No full download before playback
* Faster startup
* Lower memory usage
* Efficient bandwidth usage
* CDN delivery worldwide

To make transitions smoother, the next song can begin preloading shortly before the current one finishes.
